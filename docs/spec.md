# kenshinn_convertor — 詳細仕様

健診の問診票・検査結果票を読み取り、健康診断個人票（Excel）へ統合するツールの仕様。用語は [`../CONTEXT.md`](../CONTEXT.md) に従う。
**移植（Windows / GAS）への配慮は当面しない。macOS ローカルでの完成を最短で目指す。**

サンプル（2026-06-29 受領）に基づく確定版。未確定は §5 に集約。

---

## 0. 変換ワークフロー（全体像）

```
┌─────────────────────────────┐    ┌─────────────────────────────────┐
│ 入力①: 健診チェック表(問診票)  │    │ 入力②: 検査結果票（採血・尿）       │
│   - 手書き                     │    │   - 印字                           │
│   - JPG / PNG 画像              │    │   - 通常 2 ページ                  │
└──────────────┬──────────────┘    └───────────────┬───────────────┘
              │                                    │
              └────────────┬───────────────────────┘
                            ▼
        ┌──────────────────────────────────────────────────┐
        │ ① 抽出 (src/kenshin/extract_llm.py)              │
        │   - Claude(claude-opus-4-8) に画像を渡す         │
        │   - 健診特化のシステムプロンプトで認識を誘導       │
        │   - 構造化出力(JSON Schema)で項目→値を取得         │
        │   - 読めない/自信がない項目は _uncertain に列挙   │
        └──────────────────────┬───────────────────────────┘
                                ▼
        ┌──────────────────────────────────────────────────┐
        │ ② 算出 (src/kenshin/compute.py)                   │
        │   - BMI = 体重 / (身長/100)²                       │
        │   - 年齢 = 受診日 - 生年月日（和暦パース込み）       │
        └──────────────────────┬───────────────────────────┘
                                ▼
        ┌──────────────────────────────────────────────────┐
        │ ③ 書き込み (src/kenshin/excel_writer.py)          │
        │   - configs/<種別>.json の「項目→セル」対応表を参照│
        │   - テンプレ Excel(templates/...) を複製           │
        │   - 各セルへ値を書き込む                            │
        │   - _uncertain の項目は値を入れず黄色(#FFFF00)塗り │
        └──────────────────────┬───────────────────────────┘
                                ▼
        ┌──────────────────────────────────────────────────┐
        │ 出力: 健康診断個人票.xlsx                          │
        │   - 値が入った「個人票」シート 1 枚                 │
        │   - 黄色セル = 医師が目視で確認・記入する箇所       │
        │   - 「判定」「生活アドバイス」「医師の総合所見」は    │
        │     現状空欄（Phase 3 で自動化予定）                │
        └──────────────────────────────────────────────────┘
```

**3 段構成の意義**:
- ① と ② と ③ は**疎結合**。LLM(①)を別の OCR エンジンに差し替えても、②③ はそのまま動く。
- ③ は `configs/<種別>.json` を見るだけなので、**新しい健診種別（ライト/特定）を追加したいときはコードを書かず JSON を 1 つ足すだけ**で済む。
- `_uncertain` 列挙＋色付けの仕組みにより、**読めない値を勝手に埋めない**（医療業務で「見落としゼロ」を優先する設計）。

## 1. 入力 — 2 種類の帳票

1 人の患者について、**2 種類の帳票**を入力する。両者は **ID / 患者番号で突合**する（例: `000000000`）。

| | 帳票 | 記入 | 主な内容 |
|---|---|---|---|
| 入力① | **健診チェック表**（問診票） | **手書き** | 身体計測・血圧・視力・聴力・既往歴・自覚症状・喫煙/飲酒/運動・画像検査の所見（○囲み） |
| 入力② | **検査結果票** | **印字**（2 ページ） | 採血（血算・肝機能・脂質・糖代謝・腎機能）・尿検査 |

- 入力① は**定型レイアウト**。ただし**スキャン時の上下左右の向き違い**に備え、前処理で向きを補正する。
- 入力② は印字なので OCR は比較的容易だが、**複数の日付列**を持つ（後述 §5 Q1）。

### 健診の種別（検査項目が異なる）

健診には **企業 / ライト / 特定** の 3 種があり、種別ごとに検査項目（＝読み取り範囲・出力項目）が異なる。

- ツールは**処理開始時に種別を選択**し、種別ごとの「読み取り範囲」「出力テンプレ」を切り替える。
- **現状サンプルは「企業」のみ**。ライト・特定は実物受領後に対応（§5 Q5）。

---

## 2. 出力 — 健康診断個人票（Excel）

種別ごとのテンプレ Excel（例: 「健康診断個人票（企業健診プラン）」, セル `A1:L1` にタイトル）の決まったセルへ書き込む。
各検査ブロックは **`実測値` / `判定` / `基準範囲` / `生活アドバイス`** の 4 列構成。

### 値の出どころ（4 系統）

| 系統 | 内容 | 例 |
|---|---|---|
| **手書き転記** | 入力①からそのまま転記 | 身長・体重・血圧・視力・聴力・既往歴・自覚症状 |
| **印字転記** | 入力②からそのまま転記 | 赤血球数・GOT・LDL・HbA1c など |
| **算出** | 他の値から計算 | **BMI**（身長・体重）・**年齢**（生年月日）・**判定 A〜E**（実測値×基準範囲）・**生活アドバイス**（判定に応じた定型文） |
| **静的** | テンプレに固定 | 基準範囲・判定区分の凡例・クリニック情報・各ラベル |

## 3. セル対応づけ（企業プラン）

入力 → 出力個人票の対応。**判定・生活アドバイスの自動化範囲は §5 Q2 で確定**（下表の「判定」列は出力サンプルの値）。

### ヘッダ

| 出力項目 | 出どころ | サンプル値 |
|---|---|---|
| 氏名・ID | ①お名前＋ID（②患者番号で照合） | サンプル太郎 / 000000000 |
| 性別 | ②性別 | 男性 |
| 生年月日（年齢） | ①生年月日（年齢は算出） | S50.01.01（51歳） |
| 受診日 | ①健診日時の日付 | 2026年6月25日 |
| 既往歴 | ①既往歴 | なし |
| 自覚症状 | ①自覚症状 | なし ※出力サンプルは「エレ」と誤読 → §4 |

### 【身体計測・血圧】← 入力①（手書き）

| 出力項目 | 出どころ | サンプル | 基準範囲 |
|---|---|---|---|
| 身長/体重 | ①身長・体重 | 170.0 / 65.0 | — |
| BMI/腹囲 | BMI=算出, 腹囲=① | 22.5 / 80.0 | 18.5–24.9 / 89.9以下 |
| 最高血圧 | ①血圧①の左 | 120 | 129以下 |
| 最低血圧 | ①血圧①の右 | 76 | 84以下 |

### 【視力・聴力】← 入力①（手書き）

| 出力項目 | 出どころ | サンプル | 基準 |
|---|---|---|---|
| 視力(右/左) | ①視力 | 1.5 / 1.5 | 1.0以上 |
| 聴力 右1k/4k | ①聴力 右1000/4000Hz | 20 / 20 | 30以下 |
| 聴力 左1k/4k | ①聴力 左1000/4000Hz | 20 / 25 | 30以下 |

### 【貧血・血液一般】← 入力②（印字）

白血球数 / 赤血球数 / 血色素量 / MCH / MCV。サンプルでは白血球数・MCV が「未実施」（採用列に値が無いため → §5 Q1）。

### 【肝機能】【脂質代謝】【糖代謝・腎機能】【尿・便・栄養】← 入力②（印字）

- 肝機能: GOT(AST) 20 / GPT(ALT) 18 / γ-GTP 25
- 脂質: LDL 100(判定A, 基準60–119) / HDL 60 / 中性脂肪 90
- 糖代謝・腎: 随時血糖 90 / HbA1c 5.2、BUN・クレアチニン・eGFR は未実施扱い（§5 Q1）
- 尿・便・栄養: サンプルでは未実施

### 【画像診断・循環器】← 入力①（○囲みの所見）

| 出力項目 | 出どころ | サンプル |
|---|---|---|
| 胸部レントゲン | ①胸部レントゲン検査 所見（異常なし/あり の○） | 異常所見無 |
| 心電図 | ①心電図検査 所見の○ | 異常所見無 |

### 【医師の総合所見】

自由記述。MVP では自動生成せず空欄（医師入力） → §5 Q2。

## 4. 手書き OCR の難所（実例）

出力サンプルの自覚症状欄が **「なし」→「エレ」と誤読**されている。手書き読み取りは必ず誤りが出る前提で設計する。

- **健診用語辞書**で頻出語（「なし」「動悸」「息切れ」「胸痛」「めまい」「ビール」等）へ補正
- 確信度が低い手書き項目は**例外**として人が確認できる形にする（§5 Q3）
- 数値（身長・血圧・視力など）は**字種・桁・単位**で妥当性チェック（例: 視力は 0.0〜2.0、血圧は 2〜3 桁）

## 5. 未確定事項（★ 一緒に決めること）

### Q1. 検査結果票の「日付列」をどう選ぶか

入力②は基準値列のほかに複数の日付列を持つ（サンプル: `R07.12.01` / `R08.06.25 00:00` / `R08.06.25 11:17`）。出力は **受診日（R08.06.25）の列**を採用しているように見える。
- 暫定ルール: **受診日に一致する列を採用、その列に値が無い項目は「未実施」**。
- 同一日に複数列（00:00 と 11:17）がある場合の優先順位は要確認。

### Q2. 判定（A〜E）・生活アドバイス・総合所見の自動化範囲 ✅確定（2026-06-29）

- **判定 A〜E**: ツールが**自動算出**（実測値 × 基準範囲）。
- **生活アドバイス**: 判定に応じた**定型文を自動挿入**。→ 判定→アドバイス文の**対応表**を種別ごとに用意する。
- **医師の総合所見**: ツールは触らず**空欄**（医師が手入力）。
- → 基準範囲・判定ロジック・アドバイス対応表を**設定ファイルに外出し**（種別ごと）。

### Q3. 例外（読めない・確信度低）の見せ方 ✅確定（2026-06-29）

- **該当セルを空欄にし、セルを色付け**して「要確認」を視覚的に示す（医師がそこだけ手で埋める）。
- → 確信度しきい値を設け、下回った項目は値を入れず**塗りつぶし**。しきい値の初期値は実データで調整。

### Q4. テンプレ Excel の現物 ✅作成済（2026-06-29）

出力サンプル（写真）を基に **`templates/企業健診プラン.xlsx`** を新規作成した（ユーザー側で現物準備が不可のため）。2 シート構成:
- **`テンプレ`**: ラベル・基準範囲・判定区分凡例・クリニック情報など静的要素のみ。実測値 / 判定 / 生活アドバイス / 総合所見は空欄 → **ツールはこのシートを複製して書き込む**。
- **`記入例`**: 写真の値で埋めた検証用。Phase 1 の期待出力リファレンス。

セル位置は §3 の対応づけに一致。列構成: 左ブロック A=項目 / B=実測値 / C・D=判定 / E=基準範囲 / F=生活アドバイス、右ブロック G / H / I・J / K / L。種別ごとに 1 ファイル追加していく。

### Q5. ライト・特定プランのサンプル

検査項目が企業と異なるため、両プランの入力①・②・出力サンプルを受領後に対応。まずは企業で縦に通す。

### Q6. 入力ファイルの渡し方

①②を 1 つの複数ページ PDF でまとめるのか、画像を別々に渡すのか。突合は ID で行う前提。

## 6. 設計メモ

- **OCR/抽出 = Claude（LLM）の画像認識**（`claude-opus-4-8`）。当初 Google Vision を想定したが、
  手書き×健診特化を「認識の最中」に効かせられる LLM へ切替（2026-06-29）。健診用語の優先・
  文脈での誤読補正・項目→キーの構造化を 1 段で行える。**患者画像を API へ送る**ため要配慮個人情報の
  外部送信になる点は院内規程と整合をとる。認証は `ANTHROPIC_API_KEY`（コミット禁止）。
- 捏造防止: プロンプトで「読めない値は創作せず空欄＋ _uncertain に列挙」を厳守させ、低確信は
  **空欄＋色付け**（合意済みの例外フロー）に流す。検査結果票の数値は特に推測させない。
- 向き違いは LLM が文脈で吸収（前処理の向き補正は必須度が下がる。必要なら後で追加）。
- **健診種別ごとに「セル対応づけ」を設定ファイル（`configs/<種別>.json`）に外出し**し、コード直書きを
  避ける。企業 → ライト → 特定 を設定追加だけで増やせる形に。
- 縦に薄く通す（企業・1 患者・実測値転記）→ 横へ広げる、の順で最短到達を狙う。

### GAS / 他言語への移植のヒント

本リポジトリは Python 実装だが、設計は他言語でも素直に再現できる構造になっている。GAS で書き直す場合の対応関係:

| 本実装 | GAS での代替 | 備考 |
|---|---|---|
| `extract_llm.py`（Anthropic SDK） | `UrlFetchApp` で Gemini Vision API or Claude API を直接叩く | 構造化出力（JSON Schema）の指示を同じ要領でプロンプトに含める |
| `excel_writer.py`（openpyxl） | `SpreadsheetApp` の Range API | セル指定（"B5" など）は同じ書き方で動く |
| `configs/<種別>.json` | スプレッドシートのマスターシート or `PropertiesService` | **コードに対応表を直書きしないことが最重要**（種別追加時に改修が要らない） |
| `compute.py`（BMI/年齢/和暦） | 標準 JavaScript の Date / 自前実装 | 和暦パースは元号→西暦オフセットの辞書を用意するだけ |
| `_uncertain` → 黄色塗り | `Range.setBackground("#FFFF00")` | 「読めない値は捏造せず色付けで保留」の原則は必ず踏襲すること |

**移植時に最も重要な「設計上の原則」は3つ**:
1. **LLM への指示で「捏造禁止／読めない値は _uncertain に列挙」を必ず徹底**（医療データなので）
2. **項目→セルの対応表を設定ファイル化**（種別が増えるたびにコード改修すると保守不能）
3. **判定・アドバイス・総合所見の自動化範囲を最初から明確にしておく**（本実装は「判定＋アドバイス自動／総合所見は医師手入力」で合意済み）
